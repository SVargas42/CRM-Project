Security remediation integration (schema version 6)
The managed Core project now references Microsoft.EntityFrameworkCore.Sqlite.Core 10.0.14 and SixLabors.ImageSharp 3.1.12. These packages and their transitive dependencies must be supplied from an approved, checksum-verified offline feed, then the locked dependency graphs must be regenerated before building or publishing. They were not present in the accessible cache during implementation; their compilation/runtime integration has not been verified. Use the Sqlite.Core variant so a plaintext SQLite native bundle is not introduced alongside SQLCipher. ImageSharp adds no separate native image decoder dependency.

Database connections still use the bundled e_sqlcipher native library on macOS and Windows. The SQLCipher version probe is not evidence of FIPS validation; the deployed cryptographic modules and host configuration still require independent approval. No network package sources, telemetry, or remote image resources were introduced.

The runtime now maintains a separate 32-byte audit master secret in the OS credential store. Its credential identity is the canonical database path with .audit-master appended; this is an identifier only, never a filesystem key file. On macOS it is a second Keychain item using the existing service/account mechanism. Preserve access to both database and audit credentials. An established chain with a missing audit key or invalid signature fails closed. Do not copy a database to another path/user and assume its credential identities migrate automatically.

Schema initialization adds retained status columns, append-only image BLOB storage, and audit signatures transactionally. Existing unsigned audit records are preserved, with a keyed snapshot of their contents at migration time; their pre-migration integrity cannot be established retroactively. New events are HMAC-SHA256 chained and verified when opening connections and appending. A local chain without a separately trusted checkpoint cannot detect replacement with an older, otherwise valid complete database or removal of a valid signed suffix by an adversary bypassing database protections. Verification scans the retained history and should be performance-tested at expected audit volumes.

ImageSanitizer takes ownership of untrusted PNG/JPEG bytes and clears them even on rejection. ProfileImageService stores sanitized PNG BLOB versions using the caller's existing authorization and audit transaction. No UI upload wiring was changed. Callers of ImageSanitizer directly own and must clear its returned byte buffer. Real ImageSharp decode/metadata tests and native macOS Keychain/SQLCipher tests remain required on a prepared offline machine. The Windows focused tests use disposable encrypted databases and an in-memory credential-store fixture, not production workspace credentials.

Pre-commit security hardening
EF commands now require a thread-scoped authorized gateway; contact/organization reads validate the session, apply record grants and lifecycle filters, and commit their audit in the same SQLCipher transaction before returning. Direct synchronous/asynchronous EF reads, bulk deletes and raw SQL cannot bypass this gateway. Image processing uses a per-operation pinned allocator that clears its buffers, a fixed pinned output buffer, and early pinning/clearing in the image storage service. These are managed cross-platform APIs and add no native dependency. The new package inventory and offline feed README record all 46 signed archives; signature checks used offline revocation mode and cannot establish current revocation status or FIPS approval. Keep NUGET_CERT_REVOCATION_MODE=offline for isolated package verification/restore. Native macOS execution remains untested for these changes.

Phase 1 security gates (supersedes preview startup assumptions)
The current source refuses unprovisioned workspace access on every platform, in Debug and Release. The client must provide its approved SQLCipher FIPS distribution, approved host-policy implementation, build-embedded release verification public key, and signed complete installation inventory. The macOS host-policy adapter is deliberately unprovisioned; no global macOS FIPS switch is assumed. Each approved native provider must return SQLite INTEGER 1 for cipher_fips_status after keying. An in-memory probe runs before workspace/key-store access; the existing free SQLCipher bundle is not an accepted fallback. See docs/PHASE1_SECURITY_PROVISIONING.md for the interfaces and provisioning contract.

Phase 1 supports an authenticated directory/apphost deployment only. Earlier extracted single-file preview commands are not a supported provisioned layout; missing assembly locations, missing trust anchors/manifests, and unverified native/assets fail closed. Do not waive integrity to reuse older preview packages. Approved signing/installation protections must anchor the verifier itself and its runtime dependencies.

MacKeychainKeyStore now uses a zero-before-free native buffer for adapter-owned Keychain write storage and transfers pinned managed read buffers only after copying/native cleanup succeed. No-copy CFData is released before its external owner. Apple may copy CFData internally; immutable OS-returned Keychain data is released, not overwritten through a read-only pointer. Native macOS runtime/Keychain/FIPS/manifest tests remain required; Windows buffer lifecycle tests do not prove erasure of Apple framework internals. No new package or network dependency was introduced.
